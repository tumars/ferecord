# ferecord 动态首页：调研、设计与实施

## 结论

采用 **Blender 制作部分环境模型 + Three.js 渲染动态环境 + 原生 HTML 作品卡**。人物、藏狐与主星球保留已选定的高质量插画，环境中的书本、画框、星轨、小行星和星星为真实 3D；云团由 Blender 生成一体曲面并导出 GLB。

这一组合能够增加纵深、光照、动态与交互，同时保留已经确认的角色形象和清楚的作品入口。当前实现不是完整的角色三维重建，不能把插画做视差描述成真实的转头、眨眼、翻书。

用户最初要求调研与设计，随后要求“继续，完成改造和优化”；因此本轮已经接入首页，并以实际运行结果验证。没有只留下未完成的独立概念稿。当前为本地实现，Git 推送与线上发布另行记录。

## 当前条件与调研依据

- 站点：原生 HTML/CSS/JavaScript，主站独立发布 `sites/main/public/`。首页文字、两张作品卡、博客入口均为 HTML。
- 已选角色：短前刺、阳光神态、轻微训练线条、花衬衣、卷脚棕色长裤、厚袜和系带靴；Tibi 藏狐保留方脸、半垂眼、奶油色脸颊与格桑花发卡。用户否定了短裤凉拖方案。
- 现有资源：角色与月球是同一张透明 WebP，只有一个视角，没有背面几何、骨骼、表情或遮挡后的像素信息。
- 2026-11-17 查询 npm 后固定 Three.js 0.187.0、esbuild 0.28.2；结合 Context7 的 Three.js 官方源码示例核对了正交相机、对象选择、材质与渲染生命周期。没有使用未固定版本的 CDN。
- 本机已安装 Blender 5.4.0 Alpha。本轮实际用它导出云团，最终 GLB 为 866 顶点、1,728 三角面、39,380 字节；这证明本机资产制作链路可用，不代表全部角色已建模。

## 路线比较

| 路线 | 能获得什么 | 主要代价 | 本次取舍 |
| --- | --- | --- | --- |
| 现有图片 + CSS 分层 | 保留画质，轻量漂浮和视差 | 相机变化有限，道具没有真实几何 | 用于角色与无 3D 时的底图 |
| Blender 预渲染视频 | 可以精细制作角色与灯光，固定镜头画质高 | 镜头固定，难以响应访客的空间操作；增加视频资源 | 不作为主要背景 |
| Three.js 程序化环境 + 角色图片 | 道具、光照和星轨有真实空间，可响应卡片与鼠标 | 人物仍是图片，极端转动会暴露平面感 | 本轮采用，限制相机幅度 |
| Blender 完整角色/星球 → GLB → Three.js | 真实转头、眨眼、翻书与更大范围相机 | 需重建造型、材质、背面、绑定与动画，并重新确认形象 | 留作后续明确需求，不伪装成已完成 |

Blender 是制作工具，Three.js 是浏览器中的运行工具，二者可以协作。WebGPU 不是本轮必要条件：Three.js 官方仍将 WebGPURenderer 标为实验状态，WebGLRenderer 适合当前简单 WebGL 2 场景，因此本轮使用后者。

## 视觉设计

### 核心构图

保留“好奇心的小小宇宙”：中央人物和藏狐一起阅读，Tibi 与画海作品卡在两侧。背景增加空间层次，标题区域继续保留阅读留白。

| 层次 | 组成 | 动态与限制 |
| --- | --- | --- |
| 远景 | 奶油白/蓝调渐变、星点、小行星 | 低对比，不覆盖标题 |
| 中景 | 两条倾斜星轨、书本、微型画框、融合云团 | 缓慢漂浮，卡片联动；不是整屏同时大幅运动 |
| 主体 | 已确认的角色、藏狐和主星球插画 | 小幅浮动与分层视差，保持正面构图 |
| 内容 | 产品图标、简短介绍、真实界面缩略图、平台信息与入口 | 始终用 HTML，清楚可读、可点击、可键盘访问 |

保留默认“奶油白昼”，页脚提供“星海蓝调”。蓝调使用深蓝环境与暖色角色/卡片形成对比，保留相同内容和位置。字体、Logo 与产品名称不随主题变化。

### 紧凑作品卡（2026-11-17 修订）

用户反馈两张卡片过大，重新设计为“悬浮展签”，减少卡片对中央星球的遮挡。通过删减重复内容重组信息，不等比缩小整张卡，也不把核心文字变成小字。

- 桌面：卡片宽 252px，约 260px 高。保留图标、名称与类别、两行介绍、72px 界面预览条，以及底部平台信息与入口；较窄桌面宽 230px。卡片分别下移到星球左右两侧，角度收为 ±3°。
- 手机：横向短卡，左侧是图标与两行介绍，右侧为 88px 方形截图，底部显示平台与入口；每张约 170px 高。缩短两张卡片之间的间距，同时保留全部主要信息和独立点击区域。
- 移除原来的编号、英文类型行、重复说明段落和标签组；Tibi 与画海的真实截图、图标、目标链接保持有效。悬停、键盘聚焦及背景星轨联动沿用现有逻辑。

本轮实测：1440px 桌面卡片为 252×257px；390px 手机为 340×167px；320px 窄屏为 282×163px。320–1920px 七档宽度没有溢出，卡片不覆盖创作手记；两张卡片的键盘聚焦、背景联动、目标链接、白昼/蓝调与图片解码通过。WebKit 的 390px 横向短卡和减少动态模式通过，脚本检查与 Git 检查通过。

### 交互

| 访客动作 | 回应 | 范围 |
| --- | --- | --- |
| 移动鼠标 | 环境与插画产生不同幅度的视差 | 插画最多约 7px 横移、4px 纵移；相机只小幅变化 |
| 悬停/键盘聚焦 Tibi | 书本轻轻靠近、阅读星轨强化，短句回应 | 点击仍直接进入 Tibi |
| 悬停/键盘聚焦画海 | 画框轻轻靠近、艺术星轨强化，短句回应 | 点击仍进入原画海子路径 |
| 点击/键盘激活好奇星 | 星星短暂发亮，出现简短回应 | 语义按钮，44×44px 命中区域；不产生弹窗或强制导航 |
| 切换蓝调 | 背景、文字与环境光色同步变化 | 不持久化主题，不增加账户或存储 |
| 暂停漂浮 | CSS 动画和连续 WebGL 渲染一起暂停 | 主题切换、聚焦反馈仍可按需绘制 |

移动端沿用“标题 → 主插画 → Tibi → 画海”的自然滚动，不接管滚动或触摸拖拽，不请求陀螺仪权限。触摸设备以约 30fps 为目标，缩小道具和限制分辨率；不把桌面悬停作为获取信息的前提。

## 技术与资产

```text
Blender create-cloud.py
  → 融合曲面、减面、平滑着色
  → public/assets/soft-cloud.glb

src/universe-scene.js + Three.js
  → esbuild 固定版本打包
  → public/assets/universe-scene.js

public/index.html + styles.css + home.js
  → 静态内容先展示
  → 浏览器空闲时按需加载动态环境
  → GLB 与其他资源均从本站加载
```

- 云团使用 Blender 体素融合、平滑和减面，避免简单球体明显拼接。导出为标准 Principled 材质；不依赖 Blender 专有着色节点在网页里原样运行。
- 书本、画框、行星和星星用简单几何与圆角体构造；画框里的海景为简洁程序纹理，不新增作品版权依赖。
- 不使用实时阴影、景深、全屏泛光或物理引擎，控制渲染开销。道具共用材质，并在离开页面时释放几何、材质、纹理和渲染器。
- 背景模块在页面空闲时加载，成功渲染后柔和渐入。初次访问若系统要求减少动态效果，则不请求 Three.js 模块；纯静态内容照常展示。
- 页面隐藏、背景区域离开视口时停止逐帧渲染。分辨率上限为桌面 DPR 1.5、手机 DPR 1，并对总绘制像素设上限。
- WebGL 初始化失败或上下文丢失时恢复 CSS 星空与原插画，隐藏无意义的星星热点；上下文恢复后重新绘制。云团单独加载失败时仍有简单云团可显示。
- 场景源码和 Blender 脚本放在发布目录之外；Makers 继续发布预构建的 `public/`。依赖锁文件、源文件与打包产物一起维护，保留 Three.js MIT 许可。

## 性能预算与验证边界

- 背景打包模块目标：gzip 后不超过 190 KiB；本地离线 gzip 测量约 166 KiB。静态服务器是否实际压缩、传输耗时、缓存命中必须分别核实，不把压缩估算当成线上实测。
- 云团模型约 38.5 KiB。角色插画保持 1200×800、119,338 字节。
- 桌面目标接近 60fps、手机目标约 30fps；浏览器自动化可以验证运行、停帧和交互，不能代替具体手机的发热、能耗、持续帧率验收。
- 本轮重点验证真实背景渲染、白昼/蓝调、卡片与键盘联动、星星、统一暂停、系统低动态、无 WebGL/模块失败/无 JavaScript 的回退、响应式和模型加载。

## 本地验收结果

2026-11-17 已完成以下检查，使用实际主站页面和本机 Chromium / Playwright WebKit，未发布到线上：

- 实际 WebGL 背景成功渲染，GLB 返回 200，所有 HTML 图片解码成功；正常流程没有页面脚本错误或失败的资源请求。
- 鼠标向左右移动时产生方向相反的视差；悬停 Tibi、键盘聚焦画海时，相应星轨/道具状态和配套短句正确变化。
- 点击和键盘激活好奇星都产生反馈。暂停后对比两次画布截图完全一致，逐帧计数不再增加，同时 CSS 插画动画也处于暂停。
- 320、390、768、900、1024、1440、1920px 七档宽度，没有横向溢出，作品卡边缘均在视口内，卡片底部不覆盖创作手记。已检查白昼与蓝调截图。
- 手机视口滚动到场景之外时逐帧计数停止，回到顶部后恢复。模拟 Page Visibility 的 hidden/visible 事件也正确停帧和恢复。手机 DPR 3 环境下画布宽度仍被限制在 390px，而非 1170px。
- 初始减少动态模式不请求 3D 模块；运行中改变偏好会暂停，初始低动态后关闭偏好也能加载场景。
- 真实触发 `WEBGL_lose_context` 后恢复静态背景与插画，隐藏星星按钮；恢复上下文后重新渲染。模块下载失败、无 WebGL、无 JavaScript 时内容与链接仍存在；仅云团 GLB 失败时动态环境仍可用。
- 导航离开再后退后动态首页可以正常恢复。
- WebKit 的 390px 手机页面实际 WebGL 渲染、图片、暂停和主题切换通过；不代表 iPhone 真机能耗验收。
- `npm run build:scene`、`npm run check`、Blender 脚本语法、`git diff --check` 通过；实际执行 Blender 脚本导出 GLB 成功。背景包为 661,525 字节，本地 gzip 为 169,455 字节，符合预算。GLB 无外部图片或外链依赖。

## 官方资料

1. [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)：当前运行环境要求 WebGL 2，r163 起不再支持 WebGL 1。
2. [Three.js WebGPURenderer](https://threejs.org/manual/pages/webgpurenderer)：WebGPU/WebGL 2 后端、迁移限制与当前状态。
3. [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)：GLB 加载及可选压缩解码器。
4. [Blender glTF 2.0 手册](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html)：材质与动画导出。网页抓取当时受限，结合索引摘要与本机实际 GLB 导出验证；不以未读全文推断复杂动画兼容性。
5. [Three.js HTML 与 3D 对齐](https://threejs.org/manual/pages/align-html-elements-to-3d.html)：HTML 内容与 3D 分层呈现。
6. [Three.js 按需渲染](https://threejs.org/manual/pages/rendering-on-demand.html)、[资源释放](https://threejs.org/manual/pages/cleanup.html)：暂停与生命周期。
7. [MDN 页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)、[减少动态效果](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)：后台与可访问性策略。
